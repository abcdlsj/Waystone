# **Waystone（界石）：自部署轻度游戏远控架构设计与工程实现指南**

面向研发团队（Rust 后端/网络、Windows C++ 系统/多媒体、Flutter 客户端）的端到端设计与落地规范。聚焦"怎么做"与"最终交付体验效果"，覆盖架构边界、核心模块实现机制、交互状态机及分阶段验收标准。

# **1\. 产品定位与核心设计红线**

## **1.1 目标场景与核心痛点**

**Waystone（界石）**取意 RPG 与肉鸽游戏中“一触回城”的传送锚点，定位于**面向轻度游戏的私有化自部署远程串流软件**——将家中自建主机化作随时触达的基地，核心覆盖卡牌构筑（如《小丑牌》《杀戮尖塔》）、战棋策略、视觉小说/Galgame、二次元日常清体力及 MMO 挂机收菜等场景。

现有方案存在明显断层：

* **传统办公远控（RustDesk / 向日葵 / ToDesk）**：自建配置步骤暴露在日常使用中，帧率与音频延迟高，缺乏针对游戏悬停（Hover）、长按快进与全屏切换的输入优化。  
* **传统游戏串流（Sunshine \+ Moonlight）**：专为"客厅大屏 \+ 实体手柄 \+ 3A 大作"设计，手机触屏直接点按体验生硬，公网穿透需额外折腾异地组网，锁屏、UAC 弹窗及无黑边比例适配经常需要手动干预。

**核心设计目标**：把所有运维配置收敛在首次部署的前 5 分钟；日常连接后实现"零配置秒连、满屏无黑边、单手搓屏不误触、断连自动锁屏还原"。

## **1.2 核心体验与性能基线**

| 维度 | 目标指标 | 体验验收体感 |
| :---- | :---- | :---- |
| **端到端操作延迟** | 局域网小于 15ms；同城 P2P 直连 15\~25ms | 点击出牌、拖拽合成、抽卡音效反馈与本地平板原生应用无体感差异 |
| **单环节耗时预算** | 采集+硬编 3\~6ms；解码+上屏 3\~6ms；音频帧长 10ms | 显存零拷贝直通，彻底消除多帧排队粘滞感 |
| **首次设备纳管耗时** | 小于 30 秒 | 手机扫码或点唤醒链接即完成绑定，全程零手动输入 IP、端口与密钥 |
| **静态画面功耗控制** | 画面无变化 500ms 后自动降至 5\~10fps | 躺床玩卡牌或挂机盯梢 2 小时，手机温升可控、不烫手 |
| **自部署服务端资源** | 单静态二进制小于 30MB，空载内存小于 64MB | 1 核 1G 轻量云服务器（如 5Mbps 带宽）或家用 NAS 单容器即可稳定常驻 |

## **1.3 首版（MVP）范围红线**

为确保首版把精力全部砸进"跟手感"与"去运维感"，严格执行以下裁剪：

* **平台收敛**：被控端首版仅支持 **Windows 10 / 11（64位）**；控制端优先交付 **iOS / iPadOS 与 Android**，同步提供基础桌面控制端。  
* **信任模型收敛**：MVP 仅服务"单人私有设备池"，同池设备默认互信免确认秒连；**不做**面向陌生人的 6 位临时协助码、连接授权弹窗与多租户权限后台。  
* **周边功能裁剪**：**不做**双栏 FTP 文件管理器（仅同步纯文本剪贴板，满足粘贴密码与兑换码）、**不做**复杂自由编辑的满屏吃鸡虚拟键位、**不做** 4:4:4 无损色彩编码（统一采用硬件兼容性与功耗最优的 HEVC 4:2:0）。

# **2\. 端到端系统架构与技术栈选型**

## **2.1 总体技术栈矩阵**

| 架构分层 | 核心选型 | 选型依据与工程边界 |
| :---- | :---- | :---- |
| **自部署服务端** | **Rust (`Axum` \+ `Tokio` \+ `SQLite`) \+ 内嵌 `webrtc-rs/turn`** | 单二进制同时承载 HTTPS 管理台、WSS 信令服务与 STUN/TURN 中继服务，消除多组件拼装运维成本。 |
| **双端共享核心库** | **Rust (`str0m` 或 `libdatachannel` FFI)** | 统一封装配对鉴权、ICE 打洞状态机、DTLS 加密、音视频 RTP 封包/组帧及低延迟输入指令通道；避开体积庞大且弱网强行降分辨率糊字的 Google 原版 `libwebrtc`。 |
| **Windows 被控端** | **Rust 主控服务 \+ C++20 媒体与系统层** | 拆分为 `Session 0 系统服务` 与 `用户态桌面采集进程`（Named Pipe 通信）；采集走 **DXGI Desktop Duplication**，硬编走 **NVENC / AMF / Intel oneVPL**，音频走 **WASAPI Loopback \+ Opus**，虚拟屏集成已签名的 [**Virtual-Display-Driver (IddCx)**](https://github.com/VirtualDrivers/Virtual-Display-Driver)。 |
| **移动/桌面控制端** | **Flutter \+ `flutter_rust_bridge` \+ 平台原生硬解渲染** | Flutter 负责设备页、扫码纳管、悬浮球、胶囊热键及触控状态机；底层音视频绕过 Flutter 播放器，Android 走 **`MediaCodec` (`LOW_LATENCY`) \+ `SurfaceView` \+ `Oboe`**，iOS 走 **`VideoToolbox` \+ `CAMetalLayer` \+ `AudioUnit`**。 |

## **2.2 仓库目录结构规范（Monorepo）**

建议采用单一仓库（`waystone`）统一管理双端协议一致性：

* `crates/waystone-proto`：信令消息结构、DataChannel 二进制输入协议定义与序列化。  
* `crates/waystone-rtc`：跨端共享的轻量 WebRTC 会话管理、自适应码率控制（ABR）与本地密钥库管理。  
* `crates/waystoned`：自部署 All-in-One 服务端守护进程（含内嵌前端静态配对面板与内置 TURN）。  
* `host-windows/waystone-host-svc`：Rust 编写的 Windows Session 0 守护服务与桌面会话切换器。  
* `host-windows/waystone-capture`：C++20 编写的 DXGI 零拷贝采集、GPU 色彩转换 Shader、三家显卡硬编封装及 WASAPI 音频采集。  
* `client-flutter/waystone-app`：Flutter 跨端控制端 UI 层，以及 `android/`、`ios/` 原生硬解纹理/Surface 桥接插件。

# **3\. 模块一：自部署服务端与零配置纳管实现**

## **3.1 单容器 / 单二进制部署设计**

* **具体实现**：  
  1. 服务端首次启动时自动初始化本地 SQLite 数据库，生成服务端 `Ed25519` 身份密钥对与自签名 TLS 证书（同时支持挂载自有域名证书，若未配置域名则通过连接 Token 内置证书 SHA-256 指纹做证书固定 Pinning，免去客户端校校验报错）。  
  2. 网络端口收敛为最小集合：`TCP 8443`（同时承载 Web 管理面板与 `/ws` 信令长连接）+ `UDP 3478`（承载 STUN 打洞探测与 TURN 中继流量转发）。  
  3. Web 管理面板使用轻量静态页直接编译进 Rust 二进制，首次访问设置管理员口令后即可生成配对凭证。  
* **交付体感效果**：  
  用户在云主机或家里 NAS 上只需跑一条 Docker 命令并放行两个端口即可完成搭建；无需手动拷贝任何 `.pub` 公钥文件，也不会遇到自签证书无法连接的问题。

## **3.2 扫码 / 唤醒链接一键纳管流程**

* **具体实现**：  
  1. 用户在服务端面板点击"添加我的设备"，服务端生成有效期 10 分钟的一次性 `PairingToken`，组装为紧凑 URI：`waystone://pair?ep=host:8443&turn=host:3478&fp=<cert_sha256>&tk=<one_time_token>`，同时渲染为二维码与可复制口令串。  
  2. Windows 被控端支持粘贴该口令串完成注册；手机/平板控制端直接调用摄像头扫码或点击链接唤醒 App。  
  3. 客户端本地生成本机专属 `Ed25519` 密钥对，携带公钥、设备名、设备类型（Host / Controller）及 `PairingToken` 提交服务端核验。核验通过后，该设备永久加入当前实例的私有信任池，`PairingToken` 立即作废。  
* **交付体感效果**：  
  新装手机 App 从打开到看见家里的在线电脑卡片不超过 30 秒，全程不在手机小键盘上敲任何一个 IP 地址或端口号；私有池内的控制端点击电脑卡片直接发起基于双方公钥签名的免密握手，零弹窗秒进画面。

## **3.3 P2P 打洞优先与中继带宽保护机制**

* **具体实现**：  
  1. 每次发起远控时，双端同时收集局域网 `Host` 候选、公网 `Srflx` 候选（经内置 STUN 探测）以及内置 TURN `Relay` 候选，通过 WSS 信令实现 Trickle ICE 并发连通性探测。  
  2. 连接建立后，若选定路径为 `Host` 或 `Srflx`，客户端状态胶囊显示绿点 `直连 · XXms`；若因对称型 NAT 被迫回退至 `Relay` 路径，状态胶囊立即切换黄点 `中继 · XXms`。  
  3. **自动限流阀**：服务端内置 TURN 分配器与被控端编码器联动——一旦检测到当前会话走 `Relay` 转发且开启了"中继限速保护"（默认开启），被控端自动将视频目标码率上限钳制在服务端设定的安全水位（例如 4Mbps），防止高分辨率画面瞬间打满 5Mbps 小水管云服务器带宽导致输入卡死。  
* **交付体感效果**：  
  用户平时无感直连享受高画质，出门遇到严格运营商网络由中继自动兜底不断联，且心里清楚当前是否消耗云服务器带宽，绝不会跑爆云主机流量包。

# **4\. 模块二：Windows 被控端实现（系统穿透、零拷贝与善后）**

## **4.1 双进程特权架构：打通锁屏、重启与 UAC 弹窗**

* **具体实现**：  
  1. 安装时注册一个以 `LocalSystem` 权限运行的 Windows 服务（运行在 `Session 0`）。该服务负责维护与自部署服务端的长连接信令心跳，即使电脑刚重启停留在未登录锁屏界面也保持在线。  
  2. 当远控会话建立时，`Session 0` 服务通过 `WTSGetActiveConsoleSessionId()` 获取当前物理控制台会话 ID，利用 `CreateProcessAsUser` 在该会话下启动媒体采集与输入代理子进程，两者通过加密 Named Pipe 交互。  
  3. 后台线程持续监听桌面切换事件（`OpenInputDesktop`）：一旦检测到从普通用户桌面（`Default`）切入安全桌面（`Winlogon`，即 Windows 锁屏界面或游戏启动器触发的管理员 UAC 确认框），立即切换子进程绑定的桌面句柄并重启采集上下文。  
  4. **一键免戳密码解锁**：控制端配置开启"生物识别代填系统锁屏"后，Windows 锁屏状态下手机端自动弹出 FaceID / 指纹验证，通过后经加密通道下发凭据或触发自动登录解锁，免去在手机屏幕上逐字输入复杂 Windows 密码。  
* **交付体感效果**：  
  用户人在地铁上点开游戏启动器、遇到反作弊或更新程序弹出管理员 UAC 授权框、或者电脑刚重启停在锁屏页时，画面全程连续可见可点，彻底消灭传统用户态串流工具一遇 UAC 就黑屏假死的顽疾。

## **4.2 虚拟显示器自适应与无头（Headless）运行**

* **具体实现**：  
  1. 被控端安装包内静默集成开源已签名的 `Virtual-Display-Driver (IddCx)` 驱动。  
  2. 控制端发起连接握手时，上报自身可用视口像素尺寸、长宽比及目标帧率档位（例如 iPhone 横屏上报 `2556x1179` 约 `19.5:9`，iPad Pro 上报 `2388x1668` 约 `4:3`）。  
  3. 被控端先将当前物理显示器的分辨率、缩放率（DPI）及多屏主副拓扑保存至本地持久化快照文件（防止断电崩溃丢失原状态），随后分情况处理：  
     * 若主机未插物理显示器（无头模式）或笔记本合盖：直接激活虚拟显示器，动态注入控制端等比例分辨率（按长边归一化至 `1920` 或 `2560` 级别，配合系统推荐 DPI 放大 UI 字体）并设为主屏。  
     * 若主机插有物理显示器且长宽比不一致：挂载匹配比例的虚拟屏设为"仅在虚拟屏显示"，使物理显示器自然熄屏省电（兼顾防窥），游戏启动后自动识别全屏无黑边分辨率。  
* **交付体感效果**：  
  无论用细长的全面屏手机还是方正的 iPad 连回家，点开游戏都能严丝合缝铺满整块屏幕，没有上下或左右的大黑边，且卡牌上的小字依然清晰易读。

## **4.3 显存零拷贝（Zero-Copy）采集与硬编流水线**

* **具体实现**：  
  1. **采集层**：使用 `IDXGIOutputDuplication::AcquireNextFrame` 获取桌面帧。严禁创建 `D3D11_USAGE_STAGING` 纹理映射回 CPU 内存，必须在同一个 `ID3D11Device` 上直接操作 GPU 显存中的 `ID3D11Texture2D`。  
  2. **色彩空间转换**：在 GPU 内通过极简 Direct3D 11 Compute Shader 或 VideoProcessor 将采集到的 `BGRA` 纹理直接转为硬件编码器原生接收的 `NV12` 显存表面。  
  3. **低延迟编码配置**：将 `NV12` 显存句柄直通送入 NVENC（NVIDIA）、AMF（AMD）或 oneVPL（Intel）硬件编码器，统一输出 **HEVC (H.265) Main Profile** 码流，强制锁定以下低延迟参数：  
     * 预设选 `Ultra-Low Latency / P1`，Tuning 选 `Low Latency`；  
     * **彻底禁用 B 帧（`MaxBFrames = 0`）**，消除双向预测带来的帧重排等待延迟；  
     * 前向参考缓冲区设为单帧立即输出（`rcLookahead = 0`）；  
     * 采用无限 GOP（不周期性刷大体积 IDR 关键帧防网络尖峰抖动），仅在刚连入或收到控制端丢包重传失败的 `PLI` 请求时立即插入 IDR 帧；  
     * **静态画面动态降帧**：若 `AcquireNextFrame` 超时未捕获到桌面脏矩形变化，说明玩家正在思考出牌或看立绘，编码器在连续 500ms 静止后自动将发包帧率降频至 `5fps` 保活；一旦捕获到输入或画面变动，0 延迟瞬时拉满回 `60fps / 45fps`。  
* **交付体感效果**：  
  从画面产生变化到编码出二进制 NALU 包的总耗时稳定在 3\~6ms；看剧情、打牌思考时网络带宽回落至几百 Kbps，手机解码器几乎零发热。

## **4.4 低延迟系统内录与双端防社死静音**

* **具体实现**：  
  1. 通过 Windows Core Audio 的 `IMMDeviceEnumerator` 获取默认音频播放端点，开启 `AUDCLNT_STREAMFLAGS_LOOPBACK` 采集系统混音流（注意：即便无物理扬声器，挂载虚拟音频端点或虚拟屏音频通道也能正常出声）。  
  2. 将采集到的 PCM 数据按 **10ms 帧长**送入 `Opus` 编码器（开启 `OPUS_APPLICATION_RESTRICTED_LOWDELAY`，码率 96\~128kbps 立体声），经独立音频 RTP 轨道发送。  
  3. **被控端静音接管**：会话建立成功瞬间，读取并记录被控端物理声卡当前的静音布尔值，随后强制将物理外放端点设为静音（Loopback 内录在驱动混音前或独立虚拟通道抓取，不受物理端点静音影响，或者将默认播放切至虚拟声卡）。  
* **交付体感效果**：  
  点击按钮、抽卡出金的声音清脆跟手不滞后；哪怕凌晨两点在卧室连书房电脑玩 Galgame 或二次元手游 PC 端，书房音箱也绝对不会发出一丝声音。

## **4.5 断连后的确定性"原子善后"**

* **具体实现**：  
  `Session 0` 系统服务内设独立状态回滚器。触发条件包括：① 控制端主动点击断开；② WebRTC 连接中断且超过 10 秒重连窗口未恢复；③ 被控端采集子进程异常退出。一旦触发，按固定顺序执行：  
  1. 卸载本次会话挂载的虚拟显示器，读取连接前保存的显示器快照，调用 `SetDisplayConfig` 还原物理屏幕原有的分辨率、刷新率与多屏布局；  
  2. 恢复连接前记录的物理扬声器静音状态；  
  3. 若用户未手动关闭"离开自动锁屏"（默认开启），调用系统 API 执行锁定会话，回到 Windows 锁屏界面。  
* **交付体感效果**：  
  下班回家坐回电脑前时，物理显示器亮起、图标排列整齐如初；在公司摸鱼途中突然断网也不用担心家里电脑敞开桌面被人看见。

# **5\. 模块三：移动/桌面控制端交互与渲染实现**

## **5.1 绕过 Flutter 视频栈的原生硬解直出**

* **具体实现**：  
  1. **严禁使用 Flutter 官方 `video_player` 或软解渲染**（默认带数帧缓冲队列，会产生 50\~100ms 拖影延迟）。  
  2. 在 Android 端创建底层 `SurfaceView`，在 iOS 端创建 `CAMetalLayer`，将其置于屏幕最底层，Flutter 透明交互层（悬浮球、胶囊按键、手势检测器）覆盖在其上方。  
  3. Rust 传输引擎收到 RTP 包重组出完整一帧 HEVC NALU 后，立即通过 C FFI 塞入原生解码器并标记"立即渲染（Render Immediately）"：  
     * Android：`MediaFormat` 显式开启 `KEY_LOW_LATENCY = 1` 及厂商低延迟扩展属性，解码输出直接绑定至 `SurfaceView` 的 `Surface`。  
     * iOS：`VTDecompressionSession` 开启 `kVTDecompressionPropertyKey_RealTime = kCFBooleanTrue`，解码出的 `CVPixelBuffer` 直接交由 `Metal` 渲染上屏。  
  4. **音频播放与静音联动**：Android 使用 `Oboe` 开启 `AAudio` 低延迟模式，iOS 使用 `RemoteIO AudioUnit`，自适应抖动缓冲上限锁在 20\~30ms；连入瞬间主动检测手机系统静音状态（如 iOS 静音模式或 Android 媒体音量为 0），若处于静音则默认关闭远控声音输出并在角落显示静音小图标，手动点击才出声。  
* **交付体感效果**：  
  网络包到达手机后 5ms 内画面已经显示在屏幕上；在办公室或安静场所点开远控绝不会突然炸出游戏开屏语音。

## **5.2 轻度游戏专属触控手势状态机**

针对卡牌、战棋、自走棋最核心的"看词条怕误出牌"与"单手拖拽"痛点，直点模式下需实现一套精确的触控状态机（坐标均实时归一化映射为远端桌面绝对坐标 `0~65535`）：

| 手势意图 | 判定条件与阈值 | 下发至被控端的指令序列 | 终端反馈与体验效果 |
| :---- | :---- | :---- | :---- |
| **普通点按（Click）** | 单指按下 `Down` → 持续时间小于 `160ms` 且手指移动距离小于 `8dp` → 抬起 `Up` | `MouseMove(x, y)` → `LeftDown` → 延迟 15ms → `LeftUp` | 指哪打哪，秒点对话选项、地图节点与菜单按钮 |
| **滑移悬停看词条（Hover）** | 单指按下 `Down` → `160ms` 内手指移动距离超过 `8dp` 进入 `Hovering` 状态 → 持续滑动 → 抬起 `Up` | 滑动全程按屏幕刷新率发送 `MouseMove(x, y)`；**抬手 `Up` 时不发送任何点击事件** | 手指在手牌区横扫即可逐张浮出卡牌详情词条，松手绝不会误把牌打出去 |
| **停顿抓牌拖拽（Drag）** | 单指按下 `Down` → 原地停顿满 `160ms`（移动小于 `8dp`）进入 `Dragging` 状态 → 拖动 → 抬起 `Up` | 满 160ms 瞬间发送 `MouseMove(x, y)` \+ `LeftDown`；移动发送 `MouseMove`；抬手发送 `LeftUp` | 进入拖拽瞬间触发一次手机**清脆微震动（Light Haptic）**，明确感知"牌已抓在手里"，拖到目标区松手释放 |
| **快速取消 / 右键** | 任意位置双指同时轻拍（Two-finger Tap，接触时长小于 `200ms`） | 在当前光标位置（或双指中心点）发送 `RightClick` | 配合中度震动反馈，单手/双手随时取消卡牌选中或关闭二级弹窗 |
| **双指滚轮滚动** | 双指同向平行上下滑动 | 映射为连续高精度 `MouseWheel(delta)` 事件 | 顺滑翻看战斗日志、卡组列表与视觉小说历史对话文本 |
| **双指捏合局部放大** | 双指张开 / 捏合（Pinch） | **纯本地视图矩阵缩放平移**（不改变远端分辨率） | 遇到极细小的 PC 端背包格子或设置项时，随时放大画面精准点按 |

此外，通过侧边悬浮球可一键切换为\*\*"全屏触控板模式"\*\*（光标按相对加速度移动，单指轻点左键、双指轻点右键、单击并按住拖动），兼顾习惯传统触控板手感的玩家。

## **5.3 侧边吸附悬浮球与三套免配置胶囊热键**

* **具体实现**：  
  1. **废除顶部工具栏**：屏幕顶部区域 100% 留给远端窗口标题栏与游戏顶部状态栏。唯一入口为一个直径 `36dp` 的半透明侧边吸附悬浮球（3 秒无操作自动半隐藏至屏幕边缘且透明度降至 30%）。  
  2. **系统手势防冲突**：Android 端对悬浮球所在侧及上下热键区调用 `setSystemGestureExclusionRects`，全屏游戏下边缘侧滑需"连续两次轻滑"才触发系统级退出，彻底杜绝拖牌到屏幕边缘误触手机返回桌面。  
  3. **展开极简控制面板**：点击悬浮球展开毛玻璃小面板，首版仅设 5 个高频开关：`触控模式切换（直点/触控板）`、`场景热键预设切换`、`画质省电切换（60帧丝滑 / 45帧低温）`、`唤起系统软键盘（带 Esc/Tab/Win/Ctrl 顶栏）`、`断开并锁屏`。  
  4. **内置 3 套边缘半透明胶囊热键（支持单击锁定 Toggle）**：  
     * **预设 A（卡牌/策略）**：右侧边缘竖排紧凑悬浮 `[Space 结束回合]`、`[右键 取消]`、`[Esc 菜单]`。  
     * **预设 B（Galgame / 视觉小说单手躺玩）**：屏幕左右两侧边缘设宽 `48dp` 的近乎全透明大热区（单手大拇指随便点边缘即发送 `Enter/左键` 推进下一句），上方配一枚支持\*\*状态锁定（Toggle）\*\*的 `[Ctrl 快进]` 胶囊——点一下高亮持续按住 `Ctrl` 飞速跳过已读剧情，再点一下松开，无需手指一直死按屏幕。  
     * **预设 C（清日常轻交互）**：左下角轻量化半透明虚拟摇杆（映射 `WASD`），右下角紧凑排列 `[F 交互]`、`[Space 跳跃]`、`[1][2][3][4]`、`[M 地图]`。  
* **交付体感效果**：  
  零配置点开就能顺手玩 90% 的轻度游戏，界面清爽不挡立绘与战斗画面，单手侧躺握手机玩一小时大拇指不酸痛。

## **5.4 弱网情绪安抚与防打断机制**

* **具体实现**：  
  1. **3 秒冻结保流原则**：当网络发生瞬时丢包或 Wi-Fi 切蜂窝抖动（持续小于 3 秒）时，客户端渲染层**严禁黑屏、严禁弹出模态"正在重新连接…"遮罩框**；画面保持最后一帧清晰图像，本地绘制软光标允许手指继续移动，仅将侧边悬浮球状态圆点由绿变黄呼吸闪烁，后台静默执行 ICE 重协商或请求 IDR 帧追赶。  
  2. **超时精准归因**：若断流超过 3 秒，仅在屏幕顶部浮出一条非阻断横幅提示 `网络波动，正在恢复画面…`；若超过 12 秒彻底失联退出，报错文案必须基于信令探测结果明确区分：**"家里电脑当前已离线/休眠"** 或 **"自建中继服务器连接超时"**，拒绝含糊的"连接失败（错误码 \-1）"。  
* **交付体感效果**：  
  电梯口、地铁进站短时抖动不打断玩家出牌思路；真出了问题一眼看懂是家里停电休眠了还是云服务器挂了。

# **6\. 通信协议与状态同步规范**

## **6.1 信令通道协议（WSS）**

采用轻量 JSON（或 Protobuf）消息帧，核心信令类型收敛为 6 类：

* `DeviceHello / AuthChallenge`：基于设备 `Ed25519` 私钥对服务端随机 Nonce 签名完成双向鉴权，上报设备在线状态、当前显示器与静音概要。  
* `PeerListSync`：服务端实时向控制端推送名下私有设备池在线状态与延迟探针结果。  
* `SessionStart`：控制端携带自身屏幕像素宽高、DPI、目标帧率档位（60/45）及音频开关请求建连。  
* `WebRTCSignal`：透传 `SDP Offer / Answer` 与 `Trickle ICE Candidate`。  
* `SessionControl`：运行中动态切换画质档位、切换多显示器索引、请求立即插入关键帧。  
* `SessionBye`：携带明确退出原因（`UserHangup`、`LockAndExit`、`NetworkTimeout`），触发被控端确定性还原。

## **6.2 数据通道双轨分流设计（WebRTC DataChannel）**

输入事件一旦走单一 TCP/可靠通道，弱网丢一个鼠标移动包就会造成后续点击指令全部队头阻塞（Head-of-Line Blocking），产生"光标突然停住然后瞬移乱点"的灾难体验。因此在同一 DTLS 连接内建立两条独立 DataChannel：

1. **`input-fast`（不可靠无序通道：`ordered = false, maxRetransmits = 0`）**  
   * 专用于传输高频覆盖型状态：**鼠标坐标移动（`MouseMove`）**、**虚拟摇杆轴坐标**。丢掉上一帧旧坐标无需重传，直接用最新到达的坐标更新位置，保证弱网下光标依然跟手不卡顿。  
2. **`input-reliable`（可靠有序通道：`ordered = true`）**  
   * 专用于传输绝对不能丢失的状态边沿事件：**鼠标按键按下/抬起（`LeftDown / LeftUp / RightClick`，附带触发瞬间的精确坐标快照防错位）**、**键盘按键 `KeyDown / KeyUp`**、**Toggle 锁定状态变更**及**纯文本剪贴板同步**。  
   * **防卡键兜底**：被控端维护当前已按下的虚拟键位集合；一旦检测到会话断连或切换胶囊预设，自动遍历集合补发全部对应的 `KeyUp / MouseUp` 指令，杜绝远端游戏角色一直往一个方向死跑或 `Ctrl` 一直卡死按住。

# **7\. 分阶段交付路线图与验收标准**

```
[ MVP 阶段 (v0.x) ] -----------------------------> [ V1.0 阶段 ] ---------------------------------> [ V2.0 阶段 ]
 ├─ All-in-One 节点/信令                             ├─ WoL 局域网哨兵                                 ├─ WGC 单窗口隔离代肝
 ├─ DXGI 零拷贝 / HEVC                                ├─ 无感游戏启动台                                 ├─ WebCodecs 免安装端
 └─ 专属触控手势 / 热键                               └─ 蓝牙手柄映射 / PiP 小窗                         └─ 自升级防失联看门狗
```

## **7.1 阶段一：MVP（v0.x）—— 跑通"睡前单手搓牌"最小惊艳闭环**

* **交付物清单**：  
  1. All-in-One Rust 自部署服务端（Docker 镜像 \+ 扫码配对页 \+ 内置 STUN/TURN \+ 中继自动限码率）。  
  2. Windows 被控端（Session 0 服务穿透锁屏/UAC \+ IddCx 虚拟屏长宽比自适应 \+ DXGI 零拷贝 HEVC 硬编 \+ 静态降帧 \+ WASAPI 内录与本机自动静音 \+ 断连锁屏还原）。  
  3. iOS / Android 控制端（扫码零配置绑定 \+ 原生低延迟硬解直出 \+ Hover/拖拽/双指右键触控状态机 \+ 侧边悬浮球与 3 套内置热键胶囊 \+ 60/45 帧双档切换）。  
* **硬性准出验收标准（未达标不进入 V1）**：  
  * **前 60 秒盲测**：测试人员拿到空白手机 App，不看任何命令行文档，仅扫一次服务端网页二维码，60 秒内成功进入未插显示器的 Windows 主机画面且满屏无黑边。  
  * **卡牌实战测试**：单手握持手机在直点模式下完整通关一局《杀戮尖塔》或《小丑牌》（约 30 分钟），要求全程查看卡牌词条 **0 次误出牌**、拖拽出牌跟手、切 UAC 弹窗不黑屏、手机背部无明显发烫、挂断后电脑 2 秒内自动锁屏并恢复原物理屏分辨率。

## **7.2 阶段二：V1.0 —— 打通"随时唤醒开机 \+ 游戏启动台 \+ 手柄/挂机"主力体验**

* **核心增量设计**：  
  1. **局域网"唤醒哨兵（WoL Agent）"联动**：支持在家里常开的 NAS 或软路由上以 `waystoned --wol-agent` 轻量模式运行同一守护进程；手机端点击灰色的关机电脑时，交互合并为单一按钮 **"唤醒并连接（预计 25 秒）"**——后台由局域网哨兵代发魔术包、轮询主机服务上线、自动连入并弹出手机面容/指纹一键解锁 Windows 锁屏。  
  2. **无感游戏启动台（Launcher View）**：被控端自动扫描 Steam、Playnite 及用户手动添加的快捷方式封面；手机端首页点击游戏图标即可直接拉起对应游戏、自动套用该游戏上次使用的长宽比与胶囊热键预设，把 Windows 桌面彻底藏在幕后。  
  3. **画中画（PiP）挂机盯梢小窗 \+ 物理隐私黑屏**：刷自动战斗、排副本或挂机收菜时，一键将远控缩为手机系统级悬浮小窗（自动降为 15fps 低码率静音流），排进对局点一下瞬间全屏恢复 60fps；同时支持开启物理显示器强制全黑防窥。  
  4. **蓝牙 / 拉伸手柄即插即用 \+ 自定义按键图层**：被控端集成 `ViGEmBus` 驱动，手机接上拉伸手柄（如飞智、Backbone）或蓝牙手柄即映射为远端原生 Xbox 控制器并支持震动回传；开放可视化虚拟按键编辑与社区 JSON 预设导入导出。

## **7.3 阶段三：V2.0 —— 社交破圈与全平台应急延伸**

* **核心增量设计**：  
  1. **窗口级隔离的"安全代肝 / 同屏联机"临时链接**：突破传统远控一交权就暴露整台电脑隐私的痛点。基于 `Windows Graphics Capture (WGC)` 单窗口捕获与窗口句柄输入围栏，生成仅绑定特定游戏进程窗口的一次性分享链接——好友点开链接只能看到并操作该游戏画面（系统级拦截 `Alt+Tab`、`Win` 键、任务栏点击、剪贴板与文件读取，主号悬浮窗实时可见并可一键踢出），安全覆盖找朋友帮忙抽卡、代清体力及远程同屏玩本地双人游戏。  
  2. **免安装 Web 摸鱼应急端（含老板键）**：复用服务端同一套 WebRTC 协议栈，在浏览器内通过 `WebCodecs` 实现免安装控制端；在外部电脑浏览器打开自建域名通过二次验证即可窗口化清日常，按单键瞬间静音并伪装切换为空白文档页。  
  3. **远程升级"防失联看门狗"**：被控端执行远程自升级前自动备份旧版二进制与配置；新进程拉起后若 30 秒内未能与自部署服务端完成握手注册，守护服务立即强杀新进程并回滚至旧版本，确保人在异地升级永不失联。
